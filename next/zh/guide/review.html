翻译审校 ​

翻译审校功能帮助您确保翻译质量，支持逐段审校、质量高亮定位和批量操作。

审校流程 ​

text
翻译完成 → 质检标记 → 逐段查看质量结果 → 审批 / 拒绝 → 质量裁决（可选）→ 语义质检（可选）→ 完成

翻译作业完成后的段落状态为「已翻译」，进入审校阶段。您也可以在创建翻译作业时开启 自动审批，跳过审校流程。

段落状态 ​

状态说明可转换为
待审校 (pending)等待翻译—
已翻译 (translated)AI 翻译完成，等待审校已批准、已驳回、已修改
已修改 (edited)译文被人工修改后的状态已批准、已驳回
已批准 (approved)审校通过已修改（再次编辑）
已驳回 (rejected)审校不通过已批准、已修改、待审校（重新翻译）

审校操作已精简

审校动作只保留 审批（approve） 与 拒绝（reject） 两种。要让某段译文修订而不立即通过/拒绝，请改用段落编辑/更新入口修改译文文本——译文一旦被改过，状态会变为「已修改」(edited)。

状态流转

  • 审批操作可从「已翻译」「已修改」「已驳回」转换为「已批准」
  • 拒绝操作可从「已翻译」「已修改」转换为「已驳回」
  • 已批准的段落若需修订，先修改译文变回「已修改」，再决定是否审批/拒绝

逐段审校 ​

翻译完成后，在工作区的段落列表中逐段查看和审校翻译结果。

审校界面 ​

每段显示以下信息：

  • 源文本 — 原始内容，可切换查看 HTML 源码
  • 翻译文本 — AI 翻译结果，质量问题会在译文中直接高亮
  • 状态标签 — 带图标和颜色的状态标识（蓝色=待审校，绿色=已批准，红色=已驳回）
  • 质量指示 — 在译文单元格内以颜色块与下划线标出问题区间，悬停/点击可查看问题 code 与说明
  • 审校批注 — 审校者添加的备注信息，点击可展开查看

质量问题高亮 ​

规则质检和语义质检产生的问题会带 span（精确的源/译片段位置），段落列表会把这些问题区间在译文里高亮出来：

  • 红色 / 橙色背景 — 按 severity 区分 error 与 warning
  • 悬停联动 — 鼠标悬停问题图标，对应文本区间高亮；反之亦然（移动端为点击联动）
  • 重叠区间 — 多个问题落在同一段文字时自动合并显示，避免视觉混乱

段落导航 ​

段落表格支持键盘上下导航：

  • ↑ / ↓ 键移动聚焦行
  • 自动滚动确保聚焦行不会被表格头部遮挡

审校操作 ​

操作说明状态变化
✅ 审批确认翻译正确→ approved
❌ 拒绝标记翻译有问题→ rejected

修改译文 ​

需要修订译文时，使用段落的更新入口：

  1. 在段落行的编辑入口中修改译文文本（与可选批注）
  2. 保存后状态自动转为「已修改」(edited)
  3. 保存时会自动对译文跑一遍零配置确定性 QA（无需执行计划配置）：覆盖 untranslated、source_residual、punctuation_pairing、punctuation_missing、whitespace_irregular、repeated_space、width_mix、number_mismatch、url_email_mismatch、subtitle_line_count、leftover_placeholder、xml_tag_mismatch 共 12 项即时判定，质量问题会实时更新到该段
  4. 之后仍需在「已修改」状态下决定 审批 或 拒绝

只改译文，不改原文

段落编辑入口仅支持修改译文与批注，不能改动源文。依赖长度比阈值、术语表或多段/文档级比对的检查（length_ratio、forbidden_term、term_inconsistency、duplicate、duplicate_source_divergence）不在即时 QA 范围内，仍由翻译轮次或后续审校处理。

质量检测 ​

LinguaFlow 在翻译完成后自动检测译文中可能存在的问题，涉及四类机制：

  • 规则质检（确定性 QA）：纯规则、本地执行、可靠可复现；在翻译轮次内随执行配置自动运行并写回段落
  • 本地改写（correct）：可选的执行计划轮次，机械修复规则质检报出的高频安全问题子集（如补回丢失的引号），纯本地、不调 LLM、不新增问题
  • 语义质检（LLM 语义 QA）：可选的执行计划轮次 semantic_qa，捕获规则无法覆盖的语义错误，产 warning 级问题直接进人审
  • 质量裁决（adjudicate）：对软规则问题逐条问 AI 做误报剔除，不新增问题

历史与用途 ​

来源何时跑是否新增问题严重级别是否可入选工作流裁决
规则质检翻译轮次内、同步是error / warning软规则可裁决
本地改写（correct 轮次）执行计划中安排的轮次（翻译后）否（只改写）——
语义质检（semantic_qa 轮次）执行计划中安排的轮次是warning否（直接进人审）
质量裁决（adjudicate 轮次）执行计划中安排的轮次否——

修复与裁决各管一段

correct 轮改写译文以消除已被规则质检报出的安全问题（幂等：改写后会用同一 checker 重跑验证，改不掉就回滚保留原问题）；adjudicate 轮则只判断已有软规则问题保留 / 剔除、不改译文。二者都放在翻译轮次之后，不冲突。详见 流水线与原理 · 规则质检与 AI 质量裁决。

规则质检 code 一览 ​

执行配置 qa.checks 为 nil 时启用全部；非 nil 时按名称过滤。下表为完整清单（含 1 项文档级检查）。

code说明级别可裁决文档级
length_ratio译文长度相对原文过短/过长（按字符或词计算）error/warning✅ 软规则
duplicate相邻段落译文完全相同error❌ 硬规则
duplicate_source_divergence文档级：规范化相同源文段却出现不同译文（跨段同源异译）warning❌✅
untranslated译文与原文完全一致，疑似未译error❌ 硬规则
source_residual译文夹带源语脚本片段（假名、谚文、西里尔文、汉字残留等），按语言对分档warning✅ 软规则
punctuation_pairing目标语引号/括号/书名号等配对不平衡warning❌ 硬规则
punctuation_missing源文整类包裹标点（引号、括号等）在译文中完全缺失warning❌ 硬规则
whitespace_irregular零宽字符、NBSP、制表符、行/段分隔符等异常空白warning❌ 硬规则
repeated_space连续空格；CJK 目标语中字符间夹英文空格warning❌ 硬规则
width_mixCJK 目标语中混入半角标点，或拉丁目标语中混入全角字符warning❌ 硬规则
number_mismatch阿拉伯数字在源/译间不一致（归一化全角数字与千分位/小数分隔符后比对多重集合）error❌ 硬规则
url_email_mismatch源/译中超链接、邮箱地址集合不一致error❌ 硬规则
subtitle_line_countsrt/ass/vtt 等字幕格式下，源/译行数不一致error❌ 硬规则
forbidden_term命中词表禁译（forbidden）条目，译文中却出现 targeterror❌ 硬规则
term_inconsistency命中强制（mandatory）条目，但译文未用 target 译法warning❌ 硬规则
leftover_placeholder译文中残留 __LF_* 占位符（缺失、重复或字形偏移等三类汇总）error❌ 硬规则
xml_tag_mismatch源/译 XML 标签多重集合不一致（标签爆裂或丢失）error❌ 硬规则

source_residual 按语言对自动启用；源语言为 auto 时不生效。其中 16 项 per-batch checker 可在 qa.checks 中按名启用/排除；duplicate_source_divergence 为文档级检查（跨段对比），始终随 QA 引擎运行，不必也不能在 qa.checks 中排除。

punctuation_missing 与 punctuation_pairing 互补不重复：源文某类包裹标点在译文中完全缺失时报 punctuation_missing；译文仍有该类标点但配对不平衡时才报 punctuation_pairing。punctuation_missing 报出的安全子集可由执行计划的 本地改写轮次 自动修复，详见 流水线与原理 · 本地改写。

原文结构不会被误报为质量问题

HTML 标签、链接等原文结构在译文中会被还原回来，但 QA 引擎会把这些区段标为保护区，标点配对、空白、全/半角混用等 checker 在保护区上自动跳过——只检查译文真正写出来的文字。所以一份满是 HTML 标签的译文不会再因为标签里的英文符号被报一堆 punctuation_pairing / width_mix。xml_tag_mismatch 比对标签时还会排除 <ruby> 注音标签族，避免与 Ruby 还原策略冲突。详见 流水线与原理 · 保护区。

词表上的禁译 / 强制

forbidden_term 与 term_inconsistency 由 术语表 的 forbidden / mandatory 属性驱动，先配好条目才会触发这两类问题。

语义质检 code ​

语义质检由执行计划 semantic_qa 轮次运行 LLM 产出，覆盖规则质检难以捕获的语义错误。8 个 code 按优先级划界（同一缺陷同时命中两类时取最具体者）：

code含义
term_fidelity词表外术语的语义误译，或非词表称呼的前后漂移
calque照搬源语搭配/构词/句式的逐结构借译
omission译文整体完整但丢失某个分句/短语/语义单元（段整空归规则）
addition译文凭空塞入源文没有的语义内容（仅长度异常归规则）
grammar目标语实际不合语法（主谓/助词/时态等）
register语体/敬体/语气与源文不对位
naturalness语义可懂但表达生硬直译，作流畅度兜底
mistranslation非术语/非借译/非上述范畴的一般语义误译，作语义兜底

语义质检本轮不做裁决降噪，结果以 warning 写入段落、直接进人审，因此调节扫描范围以控制成本很重要，见 翻译配置 · 使用 · 语义质检。

规则与语义不重复

语义质检 prompt 内置排除上表的全部「规则负责」code；规则 N/A 的问题才由语义负责。要让两类问题互相不污染，保持规则质检部分启用即可。

质量指示 ​

检测到问题后，段落表格的质量指标列会显示对应的状态标记：

  • 绿色 — 无问题
  • 黄色 — 轻微问题（如源语残留、长度轻微偏差、warning 级语义问题）
  • 红色 — 严重问题（如过长/过短超出阈值、重复、未翻译、禁译命中）

点击质量标记可查看详细诊断信息（含问题 code 与说明）。带 span 的问题会在译文相应区间高亮，悬停问题图标与文本区间可联动定位。

质量检测配置 ​

在执行配置（Execution Profile）中调整质量检测参数：

yaml
qa:
  enabled: true            # 是否启用规则质检
  checks:                  # 留空（undefined）表示启用全部确定性 checker
    # - length_ratio
    # - untranslated
    # - duplicate
    # - ...
  length:
    enabled: true          # length_ratio 启用开关（旧字段，与 checks 名等价）
    min_ratio: 0.5         # 最小长度比（译文/原文）
    max_ratio: 2.5         # 最大长度比对
    unit: char             # char 或 word
  repetition:
    enabled: true          # 相邻重复（duplicate）
  untranslated:
    enabled: true          # 未翻译
  • qa.checks 为 undefined（CLI/界面未填写）→ 启用 全部 17 项确定性 checker
  • qa.checks 为具体列表 → 仅启动名单中按 Checker.Name() 精确匹配的 checker
  • 列表为空数组时视为「等价于全部」并自动改回 nil

规则质检的 select-by-name（界面上的「全部启用 / 自定义选择」）是在配置编辑器里直接勾选具体检查项启用，详见 翻译配置 · 使用。

批注 ​

在审校过程中可以为每个段落添加批注，记录修改原因或翻译建议。

批注存储在段落的 review_comment 字段中，在段落列表中可以查看。

使用场景

  • 记录修改翻译的原因
  • 标记需要后续复查的术语
  • 为其他审校者提供参考意见

批量操作 ​

当翻译段落较多时，可以使用批量操作提高效率。

选择段落 ​

在段落列表中勾选需要操作的段落，底部会弹出浮动操作栏。

批量审批 ​

选择多个段落后，点击浮动操作栏的 通过 按钮，一次性审批所有选中的段落。

批量拒绝 ​

选择多个段落后，点击浮动操作栏的 拒绝 按钮，一次性拒绝所有选中的段落。

批量操作说明

  • 批量审批时，仅对状态为「已翻译」「已修改」「已驳回」的段落生效
  • 批量拒绝时，仅对状态为「已翻译」「已修改」的段落生效
  • 不满足条件的段落会被自动跳过

一键审批 ​

在资源详情页，可以使用 全部审批 功能，将该资源下所有符合条件的段落一次性审批通过。

  • 将所有「已翻译」「已修改」「已驳回」状态的段落转为「已批准」
  • 审批后自动清除这些段落的审校批注

重新翻译已驳回段落 ​

对于已驳回的段落，可以触发 重新翻译，将这些段落重置为「待审校」状态并重新进入翻译队列。

  • 所有「已驳回」状态的段落会被重置为「待审校」
  • 清除审校者信息和审校批注

自动审批 ​

创建翻译任务时，可以开启 自动审批 选项：

  • 开启后，翻译完成的段落会直接标记为「已批准」，无需手动审校
  • 适用于对翻译质量要求不高的场景或初稿翻译

在任务创建面板中，勾选「翻译完成后自动审批」即可启用。

审校进度 ​

工作区顶部的进度条显示翻译和审校进度：

  • 蓝色进度条 — 已翻译段落占比（包含已翻译、已修改、已批准）
  • 绿色进度条 — 已审批段落占比（仅已批准）

段落分组也会显示每组的已批准数量和占比。

搜索与筛选 ​

在段落列表中可以搜索和筛选，快速定位需要审校的段落。

搜索 ​

在段落列表顶部的搜索框中输入关键词，可以同时搜索原文和译文内容。搜索为模糊匹配，输入任意关键词即可筛选出包含该内容的段落。

搜索与筛选可叠加

搜索可以与状态筛选同时使用。例如，先筛选「已驳回」状态，再搜索特定术语，快速找到需要修改的段落。

按状态筛选 ​

在段落列表中可以按状态筛选：

  • 筛选「已翻译」— 查看待审校的段落
  • 筛选「已驳回」— 查看需要重新处理的段落
  • 筛选「已批准」— 查看已通过的段落
  • 筛选「已修改」— 查看人工编辑过的段落

按质量问题筛选 ​

段落列表支持按质量问题过滤，快速定位需关注的段落。问题类型筛选已从平铺的标签改为分组下拉（可搜索、可清空，占位「按问题类型筛选」），按下列 8 个分组组织全部 25 个可筛选 code：

分组包含的 code
硬规则untranslated、duplicate、source_residual、length_ratio
排版标点punctuation_pairing、punctuation_missing、whitespace_irregular、repeated_space、width_mix
数字链接number_mismatch、url_email_mismatch
占位标签leftover_placeholder、xml_tag_mismatch
术语forbidden_term、term_inconsistency、term_fidelity
语义质量calque、naturalness、mistranslation、omission、addition、grammar、register
字幕subtitle_line_count
同源偏差duplicate_source_divergence

25 个可筛选 code 由全部 per-batch checker（16 项）、文档级检查（1 项）与语义质检 code（8 项）合并派生；后续新增 checker 会自动出现在筛选列表中。可与状态筛选、关键词搜索叠加。例如：先筛「排版标点」分组里的 punctuation_missing，集中处理译文丢失引号的段落；或筛「语义质量」分组里的 calque + warning 专看语义质检报告出的逐字直译问题。

配合 AI 质量裁决 / 语义质检 / 本地改写

  • 规则质检偏敏感，可在执行计划中加 质量裁决（adjudicate）轮次，对 source_residual、length_ratio 等软规则逐条复核、剔除误报
  • 规则查不出来的语义错误，可加 语义质检（semantic_qa）轮次补足，结果以 warning 直接进人审，无需再裁决
  • punctuation_missing 等可机械修复的安全问题，可加 本地改写（correct）轮次自动改写译文消除问题，无需调 LLM
  • 三类轮次都放在翻译轮次之后，详见 流水线与原理 · 规则质检与 AI 质量裁决

任务级资源警告 ​

作业执行过程中若某资源在语义质检扫描阶段出现软警告（如失败但允许继续），会在资源详情页与进度卡片中显示 warning_message，提示您此资料的质检不完整，需人工补查。

最佳实践 ​

审校建议

  1. 分批审校 — 按章节或段落分批审校，避免疲劳
  2. 关注术语 — 重点检查专业术语的翻译是否一致（参考 term_inconsistency / forbidden_term）
  3. 保持上下文 — 审校时注意段落之间的连贯性
  4. 记录批注 — 为重要的修改添加批注，方便后续参考
  5. 善用高亮 — 用问题区间的悬停联动，快速确认报告点对应的真实文本
  6. 善用筛选 — 按状态与质量问题筛选，优先处理有问题的段落
  7. 批量操作 — 段落较多时使用批量审批/拒绝提高效率
  8. 裁决降噪 — 启用质量裁决轮次，减少源语残留、长度异常的误报干扰
  9. 语义补盲 — 规则查不出来的语义错误，再用语义质检轮次补足
  10. 机械修复 — 对译文丢引号等可确定修复的安全问题，启用本地改写轮次自动消除
