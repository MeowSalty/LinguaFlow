项目管理 ​

项目是组织一次翻译工作的基本单位：语言方向、源文件（资源）、术语表与翻译作业都挂在项目下。

尚未跑通第一次翻译？请先看 快速开始 · Web。名词解释见 核心概念。

创建项目 ​

  1. 打开 项目 页，点击 新建项目
  2. 填写项目信息：
    • 项目名称 — 用于标识项目（最多 80 个字符）
    • 源语言 — 源文件语言，可用 auto 自动识别
    • 目标语言 — 要译成的语言
    • 启用术语表 — 是否在翻译时应用术语规则
  3. 点击 创建，再点进项目卡片进入工作区

提示

创建后可随时改名称、语言与术语表开关。本地模式下你就是唯一用户，无需关心组织归属。

项目归属（服务器模式 · 预览） ​

预览

组织与多用户归属依赖服务器模式，该模式仍在完善。个人本地使用时只需个人项目即可。

  • 个人项目 — 归属当前用户
  • 组织项目 — 归属组织（需相应权限）

项目列表 ​

首页展示所有项目列表，支持以下功能：

  • 搜索过滤 — 按项目名称或语言代码搜索
  • 统计面板 — 显示全部项目数和语言方向数
  • 排序 — 按更新时间降序排列
  • 快捷操作 — 右键菜单可查看详情、编辑、查看任务、管理术语表或删除项目

项目工作区 ​

进入项目后，顶部显示项目基本信息（名称、语言方向、更新时间）和统计指标栏：

指标说明
资源数项目中的文件总数
段落数待翻译的内容段总数
已翻译已完成翻译的段落数
已审核已通过审核的段落数
运行中作业正在执行的翻译作业数

工作区包含四个标签页：

  1. 资源文件 — 文件管理（详见下方）
  2. 段落编辑 — 翻译内容查看与编辑，支持按原文/译文搜索；段落行操作菜单可发起 单段试译预览 / 单段修订预览，满意后再应用译文；工具栏可发起 搜索替换 对译文批量查找替换
  3. 翻译作业 — 翻译作业管理（详见下方）
  4. 术语表 — 项目术语管理

管理翻译资源 ​

上传文件 ​

支持以下方式上传文件：

  • 拖拽上传 — 将文件拖拽到上传区域
  • 点击上传 — 点击上传按钮，通过系统文件选择器一次选取多个文件
  • 批量上传 — 一次最多上传 50 个文件

一次选择多个文件时，会合并为一个批次任务：上传面板按批次展示任务，而不是每个文件各占一条；状态摘要与进度按批次内文件数汇总（如「正在上传 3 个文件」），展开面板可见每个批次任务的文件名、所处阶段、上传百分比或错误信息。

提示

上传前会自动进行冲突检测。如果同名文件已存在，可选择替换或增量更新。

资源管理 ​

上传后的资源可以进行以下操作：

  • 查看 — 浏览源文件内容
  • 翻译 — 启动翻译作业
  • 替换 — 上传新文件替换已有资源
  • 增量更新 — 在保留已有翻译的基础上更新源文件
  • 下载 — 下载原始文件或翻译结果文件
  • 删除 — 删除资源及其所有段落和翻译

EPUB 特殊支持 ​

EPUB 格式文件具有专用的虚拟目录结构和章节导航，支持按章节选择翻译。若需统一全书横排/竖排，可使用 Web 工具 → EPUB 横竖排转换（本机处理、不上传），见 格式支持 · EPUB。

翻译作业 ​

创建翻译作业 ​

  1. 在项目中选择需要翻译的资源（或资源中的特定段落/章节）
  2. 选择翻译执行计划
  3. 配置作业参数：
    • 过滤配置 — 控制对已有翻译的处理方式
    • 自动审核 — 翻译完成后是否自动标记为已审核
  4. 点击 开始翻译

过滤配置 ​

创建作业时可配置段落过滤，控制哪些段落需要重新翻译：

过滤选项说明
跳过已批准跳过已审批通过的段落（默认）
覆盖未批准覆盖所有未审批通过的段落
覆盖全部覆盖所有段落，无论状态

过滤配置可在执行计划中预设默认值，创建作业时按需覆盖。

作业状态 ​

状态说明
等待中作业已创建，等待执行
运行中正在进行翻译
已暂停被手动暂停，可随时恢复（见下方）
已完成翻译完成
失败翻译失败，可查看错误信息或重试
已取消用户手动取消的作业

暂停与恢复 ​

任务列表和任务详情抽屉中提供 暂停 / 恢复 操作：

  • 暂停（等待中、运行中可用）— 优雅暂停：停止派发新批次，等待在途请求完成后冻结任务。运行中的任务需要等在途 LLM 请求收尾，界面短暂仍显示「运行中」属正常现象；等待中的任务立即变为「已暂停」
  • 恢复（已暂停可用）— 从轮次断点继续：已完成的轮次与段落直接跳过，进度计数保留，不会从头重跑
  • 暂停不会清零进度——界面保留已完成的工作量百分比，并显示「已暂停，可随时恢复」
  • 已暂停的任务仍可取消；暂停与取消互不替代：暂停是可恢复的中断，取消是终态（但失败/取消的任务也能通过「重试」从断点继续）

什么场景适合暂停

LLM 速率限额即将耗尽、需要临时让出本机资源、或想在夜间低谷再继续——暂停让任务停在轮次断点，恢复后从同一位置继续，已产出译文不受影响。

进度追踪 ​

翻译过程中通过 SSE 实时推送进度信息（支持断线重连、事件持久化）：

  • 翻译进度 — 已完成工作量 / 总工作量（单位为「段 × 轮」，见下方「进度口径」）
  • 预计剩余时间 (ETA)
  • 当前翻译速度
  • 事件序号（seq） — 保证事件顺序，重连后可精准恢复丢失的事件

进度口径：工作量而非段落数 ​

主进度按「工作量」统计：分母是已启动轮次的工作量总和（每轮 × 该轮段落数），分子是已完成部分。两点推论：

  • 新轮次启动时百分比可能暂时回落——分母只计入已经启动并得知规模的轮次，后续轮次启动会扩大分母
  • 失败、取消、暂停的任务仍显示停下时的真实比例，不会归零或冻结在旧值

轮次矩阵 ​

任务详情（桌面端）的资源表提供「资源行 × 轮次列」矩阵：列标题为该轮的模式（翻译、语义质检等），单元格展示该资源在该轮的待执行 / 执行中 / 完成 / 失败 / 跳过计数，悬停可查看轮次序号、段落数、起止时间与错误信息。任务详情顶部的进度卡还会为未完成任务展示按轮次聚合的管线条，方便定位任务停在哪个环节。移动端资源表仅保留资源名称与状态。

作业详情中的 事件时间线 会把这些事件按 seq 顺序铺成一条可滚动的时间线：

  • 实时 — 作业运行期间通过 SSE 推送新事件，自动追加到底部
  • 历史分页 — 进入一个已结束的作业时，从 REST 历史端点拉取最近一页事件；向上滚动到顶部时可 下拉加载更早的事件
  • 批次事件卡 — 每个批次翻译事件以卡片形式展示状态与摘要，点击卡片 打开右侧 批次详情抽屉
  • 批次详情抽屉 — 展示该批次的完整元数据：状态、错误信息、发送 / 接收内容、术语使用情况，以及截断 / 解析修复诊断标签（见 翻译审校 · 截断与修复诊断），便于排错与复盘
  • 跳过状态 — 因目标段状态不满足 segment_filter 而未执行的批次，会标记为 skipped（信息色），与成功 / 部分成功 / 失败区分

历史事件也可查询

任务事件不仅能在界面里看，也有对应的 REST 分页端点（按 seq 游标双向翻页），便于外部监控或导出。详见 API 概述 · 任务事件。

作业操作 ​

  • 暂停 / 恢复 — 见上方「暂停与恢复」
  • 取消 — 取消等待中、运行中或已暂停的作业（终态）
  • 重试 — 对失败或已取消的作业重新执行：失败/取消的资源重新入队，已完成轮次与已翻译段落直接跳过，从当前进度断点继续。例外：显式手选段落的任务，首个翻译轮会重译所有选中段落

术语表 ​

将术语表关联到项目，翻译时自动应用术语规则。启用后，翻译引擎会优先使用术语表中的翻译结果。

详见 术语表管理。

项目删除 ​

删除项目时会级联删除以下所有关联数据：

  • 翻译作业及其关联关系
  • 资源文件及其段落
  • 术语表条目
  • 翻译记忆条目
  • 同步任务记录
  • 活动日志和使用记录

活动日志的两种视角

项目内的「活动」是当前用户视角的过滤视图。服务器模式下，管理员可在 管理员后台 · 审计日志 查看全局审计记录。

警告

项目删除操作不可撤销，请谨慎操作。
